# Le projet d'équipe : une extension de BabStage

Par équipes de 4, vous ajoutez à l'application fil rouge une **extension**, tirée au sort en
séance 1. Le projet avance pendant les séances, en trois jalons.

## Les extensions (A à H)

- messagerie en temps réel ;
- tableau de bord pour les recruteurs ;
- correspondance entre un CV et une offre grâce à l'IA ;
- prise de rendez-vous pour les entretiens ;
- espace pour l'école ;
- version multilingue, avec l'arabe ;
- application installable sur téléphone ;
- recherche avancée avec une carte.

## Les jalons

| Jalon | Quand | Ce qui est attendu |
| --- | --- | --- |
| **J1** | fin du mois 1 (S4) | l'interface de l'extension |
| **J2** | fin du mois 2 | son API |
| **J3** | S12 | la version en ligne, présentée en soutenance |

### La liste de contrôle du jalon J1

- [ ] le backlog de l'extension est écrit et trié dans GitHub Projects ;
- [ ] les maquettes des écrans de l'extension sont faites (papier ou Figma) ;
- [ ] les composants React de l'extension s'affichent, sur des données simulées ;
- [ ] chaque membre a au moins une pull request relue et fusionnée ;
- [ ] l'intégration continue est verte sur `main`.

## Travailler en équipe : le flux GitHub

1. `main` contient toujours une version qui fonctionne ;
2. une **branche** par tâche ;
3. de petits commits aux messages clairs (« ajoute le filtre par ville ») ;
4. une **pull request** : un coéquipier relit, l'intégration continue teste ;
5. relecture faite et tests au vert : on **fusionne** dans `main`.

## Les assistants IA

Les assistants de programmation (Copilot, Claude, ChatGPT...) sont **autorisés comme binôme,
jamais comme auteur** : chaque ligne que vous poussez dans le dépôt de l'équipe, vous devez
pouvoir l'expliquer. En soutenance, une question individuelle porte sur le code de chacun.
Les contrôles et l'EFM se passent sans IA.
