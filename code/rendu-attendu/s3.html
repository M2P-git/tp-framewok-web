Rendu attendu · Séance 3 : Données et formulaires

Ce que doit afficher votre page à la fin de chaque exercice. Ce sont des images figées : elles montrent le résultat, pas le code.

Pour voir ces écrans, l'API doit tourner : node api-simulee/serveur.mjs, à la racine du dépôt des TP.

Exercice 1 · Lancer l'API et lire ses réponses

Pas d'écran à produire : on lit le JSON dans le navigateur, et l'on répond sur papier.

Exercice 2 · Les prix, et un autre salon

Les 8 prestations du barbier, avec leur prix ; le bouton dit combien il y en a.

Exercice 3 · Un message clair pour un salon inconnu

Pour un salon qui n’existe pas, un message clair à la place de « Erreur 404 ».

Exercice 4 · Les prestations depuis le serveur

Les 8 cartes du Salon Yasmine, venues du serveur (avec le bonus, la durée sur chaque carte).

Exercice 5 · Le message d'erreur

Quand le serveur ne répond pas (ici, le port 3009), un message à la place de la page vide.

Exercice 6 · Chercher un mot

Un champ de recherche sous le menu : à Rabat, « coupe » ne laisse que 3 établissements.

Exercice 7 · Le champ « Nom »

Un champ « Nom » sous le prénom ; le message suit les deux champs, à chaque frappe.

Exercice 8 · La case d'accord obligatoire

Tout est rempli sauf la case : au clic sur « Réserver », un message sous la case.

Exercice 9 · Réserver, et lire la réponse

Après la réservation, le message donne l’heure et le numéro du rendez-vous (le numéro change à chaque fois).

Exercice 10 · Un message plus aimable

Le même créneau réservé deux fois : le second envoi reçoit un 409 ; la saisie reste, l’heure est effacée.

Exercice 11 · Faire refuser une réservation

Un prénom d’une lettre, un téléphone trop court, la case décochée : le serveur répond 422, avec ses messages.

Exercice 12 · Relier les deux versions

Pas d'écran à produire : l'exercice se fait sur papier.
